# V1 Scope

## V1 Goal

Deliver a credible, deployable product demo that shows how a regulated organization moves one AI use case from intake to conditional approval with audit-ready evidence.

## Keep In V1

| Capability | Why It Stays |
| --- | --- |
| Public marketing home | Needed for LinkedIn and external sharing. |
| Public demo | Shows product value without login friction. |
| Member workspace shell | Establishes SaaS credibility. |
| Use case intake | The starting point for governed AI workflow. |
| Data Governance Agent | Strong differentiator for AI readiness under federated ownership. |
| Shadow AI tracking | Shows how unmanaged AI demand is detected, contained, or converted into governed workflows. |
| Risk and control matrix | Core regulated-enterprise artifact. |
| Model mix and token cost | Clear AI-native governance angle. |
| Testing and EWS | Shows monitoring and control operation. |
| Governance memo builder | The strongest executive/audit output. |
| Audit trail | Converts workflow into evidence. |
| Lessons learned and training | Creates enterprise-wide positive feedback loop from findings, alerts, and shadow AI patterns. |
| Platform companion positioning | Needed so buyers understand this sits beside Snowflake, Databricks, AWS, Azure, and governance catalogs. |

## De-Emphasize In V1

| Capability | Recommendation |
| --- | --- |
| Memory governance | Keep as a module but reduce prominence unless tied to sensitive data controls. |
| Skills governance | Keep as future-state or advanced governance; not central to first demo. |
| Full agent catalog | Use agents as explanatory workflow processors, not a sprawling autonomous-agent marketplace. |
| Organization/user admin | Needed before production, but not a public demo centerpiece. |
| Broad policy library | Keep policy embedding focused on the data/report/process/model-risk policies needed for the demo. |
| Deep platform integrations | Describe the integration architecture in V1; implement live connectors later unless needed for the demo. |

## Cut Or Hide From First Demo

| Item | Reason |
| --- | --- |
| Too many metrics on first dashboard | Creates “random enterprise dashboard” feeling. |
| Repeated tables with similar language | Dilutes the strongest workflow story. |
| Decorative agent names without visible outputs | Feels abstract unless tied to evidence. |
| Generic claims about all regulated environments | Better to win one concrete workflow first. |

## V1 Success Criteria

- A visitor understands the product in under 60 seconds.
- The demo tells one coherent use case story.
- The dashboard feels executive-ready, not noisy.
- The memo export looks like something a governance committee could use.
- Every object on screen has a reason to exist.
- The product is clearly positioned as an operating companion to data/cloud platforms, not a replacement for them.
- Shadow AI findings do not feel punitive; the app should show containment for risk and conversion for useful demand.
- Lessons learned should visibly improve policy, controls, training, and future approvals.

## V1 Integration Scope

V1 should show a mock integration pattern, not build every connector.

| Integration Concept | V1 Treatment |
| --- | --- |
| Snowflake | Mock metadata, lineage, sensitive tags, report data product, and usage signal. |
| Databricks | Mock Unity Catalog lineage, model/job context, quality signal, and governed data product. |
| AWS | Describe private cloud integration pattern and metadata/event ingestion. |
| Azure | Describe private cloud integration pattern and Purview/Fabric/Azure Databricks signal ingestion. |
| Data catalogs | Treat catalog entries and policy metadata as upstream inputs. |

Do not lead the demo with connectors. Lead with the governance decision those signals support.
